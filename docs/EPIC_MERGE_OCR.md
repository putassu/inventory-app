# Перетаскивание, объединение вещей, OCR и исправление review

Дата: 27.09.2026. Основание: уточнения владельца приложения. Новые требования дополняют AGENT.md; исходные шесть настроенных промптов не редактировались.

## Объединение и навигация

- При перетаскивании места, секции или вещи ближайшая прокручиваемая область движется у края экрана. Скорость увеличивается к краю; RAF останавливается после drop, dragend, Escape, ухода указателя и размонтирования. Скролл выполняется немедленно, чтобы CSS smooth не продолжал движение после отпускания мыши.
- Карточки перетаскиваются в каталоге и раскрытых местах. Для телефона и клавиатуры доступны два чекбокса и «Объединить две вещи»; диалог позволяет поменять источник и цель.
- Новая атомарная команда `merge_items` переносит **весь** известный остаток. Исходная карточка и её активные остатки архивируются, значения обнуляются; история и исходные фотографии в архиве остаются. Цель сохраняет своё имя и фото. Отмена доступна через общий журнал при отсутствии последующих изменений.
- Места источника и цели могут различаться. Если у цели несколько мест с положительным остатком, пользователь выбирает одно. Перенос в произвольное третье место этой командой не выполняется.
- Совпадают категория/подкатегории, режим учёта, единица и шаг, атрибуты, марка/модель/штрихкод, метки, пользовательское описание, OCR-текст и приватность. Сравнение строгое. Сгенерированное описание не считается подтверждённым свойством; остаётся у цели.
- Совпадают сведения активных остатков: сроки, даты, серийный номер, номер/название упаковки, свойства и приватность. Уникальные вещи, учёт только присутствия, неизвестные количества и пустые источники/цели запрещены. Примерное количество остаётся примерным.
- Серверный preview показывает целевое место и результат. Сам drop ничего не применяет. Сохраняется hash просмотренного предложения. Изменение версий или появление новых остатков после preview требует новой проверки.

## Ошибки формы

Ошибка заполнения возвращает `REVIEW_VALIDATION_FAILED` с актуальной формой. Она не включает режим конфликта версий. Изменение поля снимает старую общую ошибку; выбор обязательного действия убирает относящийся к нему блокер. Настоящие конфликты по-прежнему требуют просмотра обновлённого состояния. Предложения имеют отдельный React key, предупреждения не переносятся между карточками. Разрешённые пользователем подсказки о месте и действии исключаются из последующих представлений формы.

## OCR

Кнопка «Выполнить OCR» появляется в ручном добавлении после прикрепления фотографии. Создаётся задача `purpose=ocr`; учёт она не меняет. Каждая фотография распознаётся отдельно и последовательно, с тем же физическим GPU slot и общим admission limit. Передача только доверенной локальной модели; ограничения по размеру сохраняются (по умолчанию 512 px и 256 KiB). Обычное распознавание вещи по нескольким фото по-прежнему использует коллаж.

Полный ответ объединяется с переносами строк, показывается в редактируемом поле и сохраняется только вместе с подтверждением ручного добавления. `Item.ocr_text` — отдельный Text, максимум API 100000 символов. Есть отображение в описании карточки и редактирование. Текст включён в текстовый поиск PostgreSQL и поисковый документ; для OCR-карточки сервер закрепляет `local_only`. Миграция `af426b7d9102` добавляет поле без удаления данных.

Если модель не справилась, OCR завершается ошибкой, сохраняя уже завершённые страницы. Обрезанный по лимиту ответ не выдаётся за полный. Можно исправить частичный текст вручную. Точность мелкого текста на слабой модели и 512 px не гарантируется: следует фотографировать фрагменты крупнее. OCR не заменяет проверку человеком.

## Модели и повторы

`privacy.model_preference=default|local|cloud` задаёт предпочтение одной загрузки. `force_local=true` всегда сильнее предпочтения облака. Явное `cloud` меняет стратегию задачи, но не обходит первичную локальную проверку, политики фотографий, мест, найденных вещей или запрет внешней передачи. OCR всегда локален. В интерфейсе облако недоступно до конфигурации ключа и разрешения внешней обработки.

По умолчанию — две попытки стадии (первая и один повтор), общий лимит шесть. Для аудиосегментов и OCR-страниц лимит стадии учитывается отдельно. Битый JSON/ошибка схемы и допустимые временные сетевые ошибки повторяются с ограниченной задержкой. После исчерпания лимита форма ручной коррекции появляется сразу, без лишнего прохода через очередь. Неоднозначный смысл не запускает новые попытки «угадать» действие. При неизвестном состоянии физического инференса автоматический повтор запрещён. Квоты, запрет политики, отказ модели и обрезанный ответ имеют отдельные коды; Retry-After провайдера учитывается отдельно от backoff.

Для Google официальный идентификатор — `gemma-4-31b-it`, endpoint OpenAI compatibility — `https://generativelanguage.googleapis.com/v1beta/openai/`. Источники: [доступные Gemma](https://ai.google.dev/gemma/docs/core/gemma_on_gemini_api), [OpenAI compatibility](https://ai.google.dev/gemini-api/docs/openai). Живая совместимость конкретного аккаунта проверяется только после внесения владельцем ключа. Пример из переписки ключом не считается.

## Проверки

- Полный серверный прогон: 240 passed, 6 skipped (проверки отдельного окружения).
- Полный frontend-прогон: 90 passed; последующие изменения drag-and-drop проверены отдельным прогоном 18 тестов и повтором теста автопрокрутки. ESLint прошёл. Docker-сборка frontend успешна, обновлённый web запущен.
- Ruff прошёл. Настроенный в проекте `mypy` прошёл (9 файлов domain/settings). Дополнительный, более широкий `mypy app` выявил 60 замечаний в 18 файлах: nullable-значения, типы SQLAlchemy/Pydantic и прочие несогласованные аннотации. Полная типизация приложения остаётся отдельной незавершённой работой; прохождение текущих тестов не заменяет её.
- Интеграционные тесты: перенос между разными местами, сохранение цели, реверс, несовместимые единицы/марка/сроки, неизвестный остаток, новая партия после preview, последовательные OCR-страницы, сохранение и поиск полного текста, предпочтение модели. Подставные адаптеры не обращаются к inference-серверам.
- В Chromium живой локальный OCR синтетического снимка завершился, контрольный номер получен, текст и фотография сохранены ручной формой. Поиск по слову только из OCR вернул карточку, миниатюра загрузилась.
- В Chromium с PostgreSQL проверен реальный drag-and-drop между карточками в разных местах: до подтверждения цель имела 2 шт., после — 3 шт. в целевом ящике. Исходная карточка архивирована с нулевым остатком; собственные фото цели и исходника сохранены раздельно. Созданные для проверки карточки и место затем архивированы штатными командами; пользовательские данные не очищались.
- На длинном дереве из 45 подставных мест проверены прокрутка вниз и вверх, остановка после Escape/отпускания мыши. Запись этих мест в БД не выполнялась. На ширине 360 px форма загрузки помещается без горизонтального скролла; локальная модель выбрана, облачная недоступна до настройки.
- Все девять контейнеров работают, admission limit остаётся равным 1. Реальные вызовы моделей выполнялись последовательно. Сборка предупреждает о размере основного JS-файла (531 kB до gzip); разделение bundle по страницам пока не выполнено.
- На момент завершения этого эпика Google не вызывался. После добавления владельцем ключа начат отдельный прогон: [EPIC_GOOGLE_CLOUD.md](EPIC_GOOGLE_CLOUD.md). Автотесты, тестовые изображения и журналы остаются в игнорируемых каталогах; публикация GitHub не выполняется.
