# Рефакторинг текущего frontend

Дата: 23–24 сентября 2026 года. Основание: изменённые владельцем `README.md` и `FRONTEND_SPEC.md`, включая раздел 22. Изменяется текущий React-интерфейс, подключённый через `src/main.jsx`. Промпты и маршрутизация моделей не изменялись.

## FE-0. Сверка контрактов

Исправлены несовместимости с фактическим API: плоский review-документ, `expected_versions` в формате `item:UUID`/`lot:UUID`/`balance:UUID`, JSON-тело batch polling, `system_unspecified`, `/locations/{id}/contents`, авторизованные скачивания, версии уведомлений. Для инспекции использованы исходники и доступный позднее MCP CodeGraph.

Небольшие изменения backend:

- `task_view` дополнен `input_mode`, `parent_task_id`, `title`. Название — первые 160 символов пользовательского текста с нормализацией пробелов; без текста используется русская подпись вида ввода. Поля возвращаются через существующие scoped task endpoints, не через публичный ресурс.
- GET архивированного места возвращает 404 `NOT_FOUND` вместо успешного ответа `null`.

Это совместимые дополнения к API v1 и исправление обработки недоступного ресурса. Миграции БД не нужны. Решение не добавляет отдельные состояния учёта и не изменяет правила подтверждения.

## FE-1. Сессия, область данных, оболочка

Один HTTP-клиент хранит access token только в памяти. Cookie refresh сериализован; повтор мутации после 401 сохраняет ключ идемпотентности и тело. При смене пользователя/инвентаря запросы отменяются, запоздалые ответы отвергаются, scoped providers перемонтируются, уведомления интерфейса очищаются. Ссылки после входа возвращают на исходный экран.

Добавлены подписи полей, клавиатурные кнопки, нативный modal dialog, индикация загрузки/ошибок, мобильные переходы к задачам/истории/данным. Исправлена светлая тема при тёмной системной теме; удалена внешняя загрузка Google Fonts. CSS учитывает ширину 320 px и reduced motion. Это реализация, но не доказательство визуальной/аппаратной приёмки.

## FE-2. Каталог и ручной учёт

Каталог сохраняет базовую структуру, дополняет её фото, состоянием Active/Archived и отдельным блоком ожидающих проверки задач. Есть серверные поиск/категория/наличие, загрузка следующей страницы, список/сетка, массовые перенос и архивирование. Миниатюра без готовой thumbnail не заменяется скрытым скачиванием оригинала; оригинал открывается явно в карточке. Загрузка изображений ограничена тремя одновременными запросами.

Карточка показывает партии, остатки, неизвестность, ноль, пары/одиночные штуки, атрибуты, синонимы и историю. Ручные формы используют серверные версии и дожидаются фактического применения. Десятичные строки и шаги рассчитываются через BigInt, без двоичной арифметики Number. Атрибуты лекарства/одежды/документа редактируются по серверным дескрипторам вместо несовместимых строковых полей.

Дерево мест сохраняет свёрнутость при обновлении, подсвечивает цель DnD, запрещает циклы и перемещение системного узла, раскрывает предков назначения после успешного переноса. На телефоне доступна кнопка «Переместить». Добавление потомка и раскрытие содержимого используют реальные endpoints; рекурсивное содержимое фильтрует остатки по поддереву.

## FE-3. Проверка и сохранение

202 означает принятие подтверждения. Общий механизм сохраняет минимальные receipt IDs в sessionStorage отдельно для пользователя и инвентаря, опрашивает результат и предлагает повтор именно принятого подтверждения. Повтор после потерянного ответа использует прежние UUID и ключ. Тело команды/фото/голос в это хранилище не записываются.

Форма использует плоский `review.v1`, актуальные значения действий, ревизию и hash. Вместо гонки автосохранения — явное обновление предпросмотра или подтверждение правок одним запросом. При конфликте локальные значения сохраняются, серверные показываются рядом; требуется повторная проверка. Навигация с dirty-правками блокируется с выбором остаться/покинуть. Неизвестная версия или control блокирует подтверждение.

Inbox поддерживает создание общего предложения для атомарной проверки и отдельные подтверждения с результатом каждого элемента. Реверс открывает серверный предпросмотр в той же форме.

## FE-4. Медиа и задачи

Фото последовательно декодируются с EXIF-ориентацией, ограничиваются 1600 px, преобразуются в JPEG quality 80 без метаданных; доступны порядок, поворот и обрезка. Это формат загрузки: итоговый одиночный коллаж для слабой модели по-прежнему формирует backend со своим лимитом (обычно 512 px). Нормализация аудио — WAV PCM16, mono, 16 kHz; доступны прослушивание и обрезка. Проверяются размеры файлов и длительность готовой записи. Object URL и микрофон освобождаются при уходе со страницы.

Повтор отправки переиспользует уже загруженные файлы и идентификатор задачи. После неопределённого результата создания задачи поля блокируются до повтора того же запроса. Задачи сохраняются во вкладках «Все», «Активные», «На проверке», «Завершённые». Опрос изменений пакетный, до 100 IDs за запрос; проценты не выдумываются, длительности берутся из серверного progress/timing. Есть переходы к предложению, операции, исходной задаче и диагностике.

## FE-5. Настройки, уведомления, экспорт

Профиль, личные параметры и правила напоминаний используют общий клиент авторизации. Уведомления после изменений перечитываются с новой версией. Экспорт скачивается через авторизованный запрос и временный Blob URL. Безвозвратное удаление требует предпросмотра и отдельного неотмеченного подтверждения; отображается период отмены. Во время проверки реальное удаление не запускалось.

## FE-6. Администрирование

Проверка и применение настроек разделены, desired/effective и необходимость перезапуска видимы. Сокращение сроков хранения требует отдельного подтверждения. Исправлены доступ к моделям, вывод health/trace, очередь и ожидание reindex job. Восстановление GPU требует неотмеченного по умолчанию подтверждения физической остановки. GC честно описывает полную серверную очистку: его текущий preview покрывает только orphan media. Во время проверки GPU recovery, GC и изменения реальных политик не выполнялись.

## FE-7. Проверки и границы результата

Проверено локально на синтетических данных:

- `npm.cmd test` — 57 тестов, 13 файлов; затем отдельный тест блокировки повторного submit ручной формы — 1 passed. Всего 58 проверок. Включены текущие и исторические v1 тесты. Новые проверки покрывают 401/retry/scope, десятичные значения, receipt и двойной клик, дерево, настройки, review/hash/dirty/conflict/unknown schema. Старый тест настроек исправлен: ожидание загрузки административной секции и выбор поля по подписи, а не любого spinbutton.
- `npm.cmd run build` — production-сборка успешна.
- `.venv\Scripts\python.exe -m pytest tests/integration -q` — 117 passed, 6 skipped; затем отдельно новый `test_frontend_contracts.py` — 2 passed. Интеграционные fixtures создают временную SQLite БД.
- Ruff для двух изменённых backend-файлов — успешно.
- `npm.cmd run lint` — успешно после итогового форматирования.
- HTTP dev smoke: `/` и `/items/example` возвращают HTML 200, `/health/ready` — JSON 200, `/api/v1/me` без токена — JSON 401. Это проверка proxy/SPA, не браузерный E2E.

Полная приёмка F-01…F-50 не объявляется. В этой сессии браузерные инструменты вернули `Browser is not available` для IAB и Chrome. Поэтому нет подтверждения визуального вида, настоящего DnD, камеры/микрофона, EXIF в браузере, Android WebView и поведения на реальном телефоне. Модельный smoke с Ollama/LiteLLM повторно не запускался: инференс и промпты не изменены. Пользовательские фото/голос не использовались.

Остаются границы API из раздела B ТЗ: роль членства не возвращается в `/me`; фото мест не поддерживаются; серверных totals для всех списков нет; photo_region не имеет завершённого редактируемого контракта. Такие controls блокируют подтверждение. История задач сейчас загружается страницами целиком; для очень больших инвентарей нужна отдельная серверная выборка активных задач и постраничная история. Автоматическое сохранение незагруженных файлов и восстановление тела незавершённой отправки после закрытия вкладки не реализованы. Многошаговая групповая загрузка отдельных наборов материалов и полная аппаратная матрица остаются отдельной работой; объединение уже созданных предложений реализовано.

Файлы тестов, `.cache`, локальная БД и `frontend/run_cases.js` исключены из Git; frontend-тесты также исключены из Docker build context. На этапе рефакторинга коммиты и публикация не выполнялись; отправка исходников производится отдельным шагом по запросу владельца. Запущенные сервисы и их данные не пересоздавались. Новая сборка находится в `frontend/dist`; работающий контейнер использует прежний образ до штатной пересборки web. Два backend-изменения требуют обновления API-процесса.
