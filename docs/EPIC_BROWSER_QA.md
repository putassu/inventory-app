# Браузерная проверка и исправления, 24 сентября 2026

## Среда и объём

Текущий React-интерфейс проверен через Playwright в Chromium на работающем backend: реальные операции, отрицательные сценарии, потеря HTTP-ответов после принятия записи сервером, обновление страницы и мобильная ширина 320 px. Промпты не менялись.

Среда: Compose `inventory-refactor-test`, nginx `http://localhost:18080`, API `58000`, Vite `5173`. Основной `docker-compose.yml` использует другие опубликованные порты. Gemma3:4b и BGE-M3 — Ollama, аудио — настроенная доверенная local-gemma-4-e4b. Конфигурация первичной проверки из развёрнутого реестра не заменялась автоматически.

Созданы отдельные вещи и места `UI-2409`, синтетические цветные изображения и WAV с тишиной. Существующие личные вещи не редактировались. Тесты, фото, WAV, выгрузки, скриншоты и браузерные журналы исключены из Git. Публикация в GitHub в этом эпике не выполнялась.

## Исправления

| Область | Что исправлено |
|---|---|
| Диалоги | CSS превращал кнопки сохранения/отмены в маленькие кнопки закрытия. Правило ограничено заголовком. Формы партий и поля помещаются на узком экране. Кнопка сохранения карточки связана с формой, работают required-проверки. |
| Остатки | Строковый ноль `0.000000` больше не разрешает расход/перенос. Неизвестный остаток переносится целиком. Смена источника сбрасывает несовместимое назначение/количество. |
| Партии | Исключены архивные партии; разделение/объединение запрещены для присутствия и уникального экземпляра. Для разделения нужен положительный известный остаток, для объединения — две активные партии. Исправлены месяц/неизвестность срока и дата открытия при разделении. |
| Пары | Точное отображение `1 пара`, `2 пары`, `5 пар`, `1 пара + 1 шт.` без float. Поступление новой одежды парами из review сохраняет `counting_unit=pair`; базовый учёт остаётся в штуках. |
| Review | Поля сгруппированы по действиям, второстепенные сведения свёрнуты. Видимость зависит от новой/существующей вещи, режима учёта и партии. Исправлены вложенные значения, false/null и типы чисел. |
| Предпросмотр | Форма, групповые подтверждения и история показывают подписанные значения «до → после». JSON находится в свёрнутых технических данных. |
| Receipt | GET предложения возвращает связанный receipt после принятия подтверждения. После потери ответа/reload клиент восстанавливает ожидание и результат без нового подтверждения. |
| История | Журналы операций и очередь review сортируются по времени создания, затем ID. Курсор соответствует порядку; старые курсоры поддерживаются в своей области данных. |
| Медиа | Effective limits проверяются до upload. Живой предпросмотр обрезки/поворота, длительность аудио, обрезка с запятой, русские ошибки декодирования и микрофона. |
| Черновик | Уход с неотправленным текстом/медиа требует решения пользователя. Успешная отправка открывает задачу. Закрытие вкладки вызывает штатное предупреждение браузера. |
| Задачи | Retry открывает дочернюю задачу, ручное продолжение — предложение. Ошибка сопоставления модели объясняется текстом с диагностическим кодом. |
| Сессия/профиль | Сетевой сбой при восстановлении не подменяется ошибкой пароля; сохраняется глубокая ссылка. После сохранения профиль и версия обновляются в общем контексте. AbortError не показывается как ошибка сети. |
| Каталог | Применяется компактный режим, семантические совпадения подписаны. Ошибка декодирования миниатюры показывает заглушку. |
| Массовый перенос | Выбор назначения обязателен; «Место не указано» передаёт ID системного места вместо null. В каталоге не перечисляются места с нулевым остатком. |

## Автоматические проверки

Frontend: **71 passed, 15 файлов**, `npm.cmd test`. Backend: **185 passed, 6 skipped**, полный локальный pytest. Пропуски относятся к явно включаемым инфраструктурным сценариям настоящего PostgreSQL, Redis loss и backup. Новые HTTP-контракты проверены.

Регрессии покрывают Decimal/пары, типы и вложенные поля review, сетевые ошибки, восстановление receipt, хронологический курсор и effective media limits. Локальные тесты исключены из Git по требованию владельца. Числа в исторических отчётах относятся к другим прогонам и наборам инфраструктурных проверок.

ESLint, Ruff изменённых backend-файлов и production-сборка Vite прошли. Backend обновлён штатно, frontend собран в `inventarizator-web:latest`, пересоздан только `web`. На `localhost:18080` повторный обход 13 основных маршрутов дал 0 необработанных JavaScript-ошибок и 0 сообщений console.error; страницы не имеют горизонтального переполнения при 1280 px. Это результат отдельного чистого прогона, без ранее намеренно вызванных 401/409 и сообщений HMR.

Локальные копии скачанного экспорта удалены после проверки загрузки. Тестовые карточки архивированы; их история и синтетические файлы остаются в локальном проверочном стеке.

Финальный образ содержит bundle `index-D6aSB24C.js`. Повторный обход основных маршрутов при 320 px также прошёл без необработанных JS-ошибок и горизонтального переполнения. Проверены сохранение тёмной темы после reload, визуальный экран ввода и диалог шириной 282 px. Ручное продолжение задачи открывает review. Исходные системная тема и обычный режим каталога восстановлены. `git diff --check` прошёл; служебные материалы Playwright игнорируются.

## Границы

- Это не прохождение всех сочетаний F-01…F-50. Android/WebView, аппаратная камера/микрофон, EXIF разных телефонов, память больших файлов и screen reader требуют отдельной приёмки.
- Маленькая Gemma ошибается: два прогона дали `UNKNOWN_MODEL_CANDIDATE`. Строгая проверка ссылок сохранена, доступна ручная форма. Промпты не ослаблялись ради smoke.
- Фото мест не имеют согласованного API. Многошаговый composer и восстановление его содержимого после закрытия вкладки остаются ограничениями.
- На пользовательских данных не запускались purge, GC, смена политик хранения, GPU recovery, физический сбой БД и backup/restore. Административные экраны проверены в режиме чтения; инфраструктурные доказательства — в отдельных эпиках.
- Большой каталог, все роли/инвентари и все конфликты данным браузерным прогоном не покрыты. См. оставшиеся B-ID в [ТЗ](FRONTEND_SPEC.md).

Контракты API расширены аддитивно, миграция БД не требуется. Обновление API/workers/web не требует удаления контейнеров данных или volumes.

Последующее обновление API/web, исправление границы транзакций и прогон личных кейсов описаны отдельно в [EPIC_REAL_CASE_QA.md](EPIC_REAL_CASE_QA.md). Указанные выше bundle и числа тестов относятся к этому первоначальному браузерному прогону.
