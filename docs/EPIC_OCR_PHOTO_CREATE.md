# OCR и добавление вещи по фото без названия

Дата: 03.10.2026.

## Причина и исправление

Мобильный клиент получил LOCAL_CONNECTION после трёх попыток OCR. Контейнеры были запущены, но Ollama на хосте не работал. OCR выбирал local_vlm и создавал адаптер с endpoint Ollama, хотя доверенная первичная Gemma-4-e4b отвечала. Ollama запущен с одним потоком и одной загруженной моделью; доступ к /api/tags из ML-контейнера восстановлен.

OCR теперь выбирает локальный deployment privacy_asr и передаёт его endpoint_ref в адаптер. В текущем развёртывании используется Gemma-4-e4b на as.rsmu.ru. Сохраняются общий GPU-slot, последовательная обработка страниц, лимит 512 px, до трёх попыток и запрет внешнего fallback. Исходные промпты не изменены.

Кнопка «Выполнить OCR» извлекает полный текст для поиска; не создаёт карточку и не заполняет её свойства. Назначение пояснено рядом с кнопкой. Ошибка соединения теперь описывает недоступность модели со стороны сервера, материалы и частичный текст остаются доступны.

## Добавление

- Название заполнено: прежнее ручное поступление с фотографиями, без LLM.
- Названия нет, фото есть: POST /tasks с input_mode=photo, обычная задача учёта, выбранное место и модель. Карточка сразу создаётся в состоянии processing, далее действует общий механизм распознавания и проверки.
- Названия и фото нет: предупреждение, без пустого поступления и без задачи.
- Существующая вещь: пополнение остаётся ручной командой.

В режиме распознавания вместо ручного количества/дополнительных свойств отображаются пояснение и выбор модели. Загрузка фотографий кэшируется отдельно для каждой политики. OCR и обычное ручное сохранение используют local_only; явный выбор облака при распознавании допускает cloud_allowed, но серверная проверка приватности остаётся обязательной. При потере ответа повторяется тот же запрос и client_request_id, материалы блокируются до выяснения результата.

## Проверка

30 профильных backend-тестов прошли: OCR с Ollama и доверенным endpoint, последовательные страницы, полный текст и поиск, основной пайплайн и приватность. Все 104 frontend-теста прошли; новые проверки покрывают пустой ввод, фото без названия, ручное добавление с фото и повтор после потери ответа. Ruff, ESLint и сборки Docker прошли. Сохраняется прежнее предупреждение frontend о размере JS-бандла более 500 kB.

В браузере на ширине 390 px пустая форма показала ожидаемую ошибку. Реальный OCR через Gemma-4-e4b вернул обе строки синтетического изображения точно. Затем кнопка «Добавить вещь» с фотографией и пустым названием приняла задачу с HTTP 202 и сразу вернула ID новой карточки. Запросы к моделям отправлялись строго последовательно. Тестовые файлы и ключи не публикуются.

Полный локальный прогон завершился за две стадии без ошибок: Gemma-4-e4b → Ollama gemma3:4b. Создана неподтверждённая карточка техники, количество 1, миниатюра загрузилась. В отдельном облачном прогоне первичная проверка прошла, но Google вернул серверную ошибку на трёх последовательных попытках cloud_extraction (MODEL_UNAVAILABLE). Приложение сохранило красную карточку для ручной проверки. Это ограничение живого облачного прогона; облако не отключалось, прокси не добавлялся.

После небольшой правки очистки устаревшего предупреждения повторно прошли 5 профильных frontend-тестов, включая новый тест смены пустого ввода на фото. Финальная сборка web развёрнута. Обе созданные тестовые карточки архивированы, соответствующие задачи отменены после завершения, чтобы не оставлять их в очереди проверки. Исходная пользовательская задача OCR не перезапускалась автоматически.
