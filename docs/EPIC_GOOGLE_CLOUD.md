# Проверка Google Gemma

Дата: 27.09.2026. Владелец добавил ключ в игнорируемый `.env.local` и разрешил последовательные тесты. Позднее отдельно указал не направлять запросы через прокси 10801. Это указание применено: `INV_CLOUD_PROXY` удалён, системные proxy-переменные не используются.

## Изменения

- `CloudAdapter` поддерживает прежний OpenAI-совместимый интерфейс и родной Google `generateContent`. Выбор явный: `INV_CLOUD_API=openai|google`; автоматического переключения провайдера или повторной внешней отправки нет.
- Для текущего Google настроены `INV_CLOUD_API=google`, URL `https://generativelanguage.googleapis.com/v1beta/`, модель `gemma-4-31b-it`, `INV_CLOUD_JSON_MODE=false`, `INV_CLOUD_REASONING_EFFORT=minimal`. Ключ остаётся только в окружении серверов.
- JSON-режим провайдера отключён после ошибок при проверке совместимости. Это не отключает `parse_json`, проверку схемы, допустимых ссылок, нормализацию и ручное подтверждение результата.
- Оригинальный системный промпт передаётся в `systemInstruction` без изменений. Изображение — один JPEG в `inlineData`. Части ответа `thought=true` исключаются; обрезанный ответ и отказ модели имеют отдельные ошибки. Некорректный ответ не сохраняется как успешный.
- Явный HTTP-транспорт унифицирует проверочные и рабочие вызовы. Автоматических ретраев HTTP-библиотеки нет; повторами управляет существующий pipeline.
- Административный health-check запрашивает короткий JSON и не более 256 выходных токенов. Лимит обычной задачи этим не меняется.
- В локальный verify overlay добавлен профиль `cloud` с одним worker и памятью 192 MiB. Лимиты `queue.cloud_concurrency=1`, `queue.max_pending_total=1` сохранены.
- Полный запуск обнаружил ошибку регистрации CloudWorker: arq читает `__dict__` и не видит унаследованные `functions`. CloudWorker получил явные настройки обработчиков; добавлены пять регрессионных тестов через настоящий `arq.worker.get_kwargs`. После исправления ранее принятая задача продолжилась из очереди без повторной отправки.
- Подпись стадии в интерфейсе исправлена на «Распознавание облачной моделью»: облако может быть выбрано сразу, а не только как резерв.

## Полученные результаты

- Авторизация Google прошла; список моделей подтвердил `gemma-4-31b-it` как доступную. Секреты в отчёт не выводились.
- OpenAI-совместимый endpoint давал как успешные короткие ответы, так и HTTP 500/503 и тайм-аут. Устойчивую работу этого маршрута не заявляем.
- Родной Google API успешно обработал короткие запросы с отдельным системным промптом из Windows и Docker. Наблюдаемая длительность успешных диагностических запросов — примерно 24–35 секунд; это измерение, а не обещание будущего времени ответа.
- После согласования параметров транспорта административная кнопка «Проверить подключение» вернула HTTP 200 и `verified_connection=true`. Рабочий запрос шёл напрямую, без прокси. Причина вариативности ответов Google полностью не установлена; один успешный health-check не гарантирует доступности следующих запросов.
- Проверка изображения выполнена только на синтетическом рисунке кружки. Первая попытка завершилась сетевым обрывом; один последовательный повтор прошёл за 42,5 секунды. Исходный `gemma_core_vlm.j2` дал корректный JSON: `add_item`, нормализованный `receive_stock`, категория `dishes`, количество `1`, единица `pcs`. Ответ прошёл схему и нормализацию приложения. Модель назвала кружку керамической, хотя материал рисунком не доказан: это предположение требует проверки пользователем. Фотографии, документы и голос владельца в Google в этом прогоне не отправлялись.
- 64 теста адаптеров/медиа и 21 интеграционный тест pipeline/приватности прошли. После последней правки транспорта отдельно прошли все 11 новых контрактных тестов. Ruff, настроенный mypy (domain/settings) и `git diff --check` прошли. Все шесть исходных промптов совпадают с baseline.
- Полный браузерный сценарий завершён на синтетическом JPEG 512×512: выбор облака → загрузка → локальная проверка `gemma3:4b` (39,619 с) → Google `gemma-4-31b-it` (53,717 с) → форма проверки → сохранение. Trace задачи `d94b3694-c6c8-41f1-b4e2-9cc6f1445c4f` содержит ровно два успешных модельных вызова, по одному на стадию; итог — `succeeded / saved`. Ожидание облачной очереди во время исправления CloudWorker (161 с) не включено во время inference.
- В форме вручную исправлены название и категория на «Посуда»; количество `1 шт.` и фото сохранились. Подтверждение принято с HTTP 202 и применилось примерно за 3,7 с. Проверены запись в истории, фотография в карточке и миниатюра 256×256 в каталоге после прокрутки к карточке. Созданная только для проверки кружка затем архивирована через интерфейс; пользовательские вещи не изменялись.
- После исправления регистрации воркеров прошли ещё пять регрессионных тестов; ESLint для изменённой подписи и production-сборка frontend прошли. Обновлённые cloud worker и web развёрнуты.

## Граница проверки

Владелец явно разрешил оставить облако включённым для дальнейшего использования. Разрешение применено через административный API: cloud_primary включён, `routing.external_enabled=true`, `routing.cloud_primary_ref=cloud_primary`, очередь cloud возобновлена. Тайм-аут внешнего вызова — 120 секунд, без изменения лимита одновременных задач. Прокси не используется. Локальная первичная проверка и остальные ограничения приватности сохраняются.

Cloud worker запущен с лимитом памяти 192 MiB и политикой перезапуска `unless-stopped`; для повторного развёртывания нужен профиль `cloud`. При загрузке пользователь выбирает облачный маршрут в поле «Модель распознавания»; локальная обработка остаётся доступной.

Итоговая проверка: все десять контейнеров работают, применённая и желаемая ревизии настроек совпадают (2), cloud_primary включён, очередь cloud не приостановлена. Задач в обработке и ожидающих inference нет, GPU idle; одно существовавшее предложение ожидает ручного подтверждения и оставлено без изменений. Последовательный режим сохранён. Это успешная проверка одного полного фото-сценария, а не гарантия точности всех распознаваний или бесперебойности Google.

Автотесты, синтетические изображения и промежуточные диагностические файлы находятся в игнорируемых каталогах. Изменения не публиковались в GitHub.
