# Редактирование вещей и настраиваемые атрибуты

Дата: 01.10.2026. Реализовано по запросу владельца: подтверждённая вещь редактируется одной формой, список необязательных полей настраивается, пользователь может создавать собственные атрибуты, например boolean «На продажу».

## Путь пользователя

В открытой карточке рядом с «Пополнить» находится кнопка **«Редактировать»**. Она открывает предзаполненную форму: название, категория, фотографии, количество, место, срок, свойства и OCR. Дополнительные сведения свёрнуты. Для нескольких остатков форма показывает отдельные строки; неизвестный остаток остаётся неизвестным. Режим учёта и базовая единица существующего учёта не переопределяются этой формой. Для счётных вещей можно отображать/вводить штуки или пары с пересчётом в базовые штуки; одиночный носок не округляется.

«Сохранить изменения» — явное подтверждение атомарного набора существующих команд update_item, update_lot, set_quantity, move_stock. Это не receive_stock: количество устанавливается, а не добавляется заново. При несовпадении версий сохранение требует повторного просмотра актуальной карточки. Очередь подтверждения и идемпотентность остаются общими с остальным приложением. LLM для этих изменений не используется; отдельная кнопка OCR вызывает распознавание только по явному запросу.

Новые фото добавляются к сохранённым, проходят прежнюю CPU-подготовку миниатюр. Удаление существующего фото не подменяется добавлением пустого массива. Старые нулевые строки после переноса скрыты, если у той же группы есть остаток; полностью нулевое количество остаётся доступным для исправления.

В **Настройки → Поля вещей** доступны стандартные необязательные поля и собственные свойства. Настройки относятся к текущему инвентарю и действуют в ручном создании, редактировании и актуальных формах проверки. При отключении скрывается пустое поле, но заполненные сведения остаются видимыми и редактируемыми: скрытие не удаляет данные. Boolean false и число 0 считаются заполненными значениями.

Собственный атрибут имеет название, неизменяемый технический ключ, тип boolean/string/decimal/date, список категорий и переключатель показа. Пустой список категорий означает все категории. Поддерживается до 50 определений. Сохранённое поле можно переименовать и выключить; тип и ключ не заменяются, удаление определения не разрешено. Это сохраняет интерпретацию уже записанных значений и истории. Несохранённое новое поле можно убрать из формы.

Для текущего инвентаря через интерфейс добавлен включённый флаг **«На продажу»**. Другие настройки пользователя не изменены.

## Данные и API

- `Workspace.item_fields`: JSON с `hidden_fields: string[]`, `custom_fields: {key,label,type,categories,enabled}[]`.
- `Workspace.item_fields_version`: отдельная версия настроек, независимая от версии предметного учёта.
- `Item.custom_attributes`: JSON значений по ключам определений. Категорийные `attributes` сохранены отдельно. Смена категории не стирает пользовательские свойства.
- `GET /api/v1/item-fields`: текущая версия, настройки и `builtin_fields` с допустимыми ключами/подписями.
- `PATCH /api/v1/item-fields`: `expected_version`, `hidden_fields`, `custom_fields`, обычные Bearer, X-Workspace-ID и Idempotency-Key. Требуются права записи в текущий инвентарь. Версионный конфликт — 409, неверное определение или смена типа — 422. Успешный неизменный повтор воспроизводит прежний ответ. Изменение фиксируется в audit.
- `receive_stock`, `verify_item`, `update_item`: поле `custom_attributes`; `update_item` дополнительно принимает `media_ids` для добавления фото. При непереданном custom_attributes обычная правка сохраняет прежние значения; переданный словарь заменяет набор пользовательских значений.
- `GET /forms` и review form: `custom_attributes.<key>`, типизированный control, новый необязательный `hidden: bool=false`. Клиент скрывает только пустое необязательное поле. Правки custom_attributes в review проходят типовую валидацию и общий preview.

Boolean хранится именно JSON boolean: строки «false» и числа 0/1 вместо boolean не принимаются. Decimal передаётся строкой, до 14 цифр перед запятой и 6 после неё; допускаются отрицательные значения, исключены NaN/Infinity. Дата — ISO YYYY-MM-DD. Текст — до 2000 символов. Неизвестные ключи запрещены. Собственные атрибуты вводит пользователь; промпты не изменены для их автоматического угадывания. При объединении вещей custom_attributes должны совпадать так же, как прочие свойства.

Миграция `d41e8b627a03` после `c90a51d77e20` добавляет три поля без очистки старых карточек. Перед применением сделана локальная резервная копия БД. Схема и значения попадают в обычный backup; значения вещи и изменения присутствуют в истории через общий интерпретатор. Тестовые материалы и резервная копия остаются в игнорируемых каталогах.

## Изменённые компоненты

- `app/domain/item_fields.py`: определения, разрешённые необязательные поля, типы и генерация полей формы.
- `app/api/item_fields.py`: доступ, версии, идемпотентное сохранение настроек и audit.
- ORM, миграция, schemas/contracts, inventory и proposals: хранение, валидация, фото, preview/apply, работа review и совместимость с прежними полями.
- `frontend/src/components/operations/EditItemModal.jsx`: единая форма редактирования с фото и несколькими остатками.
- `frontend/src/utils/editItem.js`: построение атомарных команд, пары и версии объектов.
- `frontend/src/components/ItemFieldsSettings.jsx`: список полей, определения и справка настроек.
- `frontend/src/utils/itemFields.js`: чтение/правка вложенных значений и правила видимости.
- ItemDetail, ReceiveStockModal, ReviewField и review utilities используют общие определения. Прежняя дублирующая форма update из ItemOperationsModal удалена; архив/восстановление/синонимы сохранены.

## Проверка

Проверены определения/версии/повтор PATCH, изоляция workspace, типы и ложные boolean-значения, сохранность при скрытии, запрет смены типа, форма review и её публичная схема, добавление фото к существующей вещи, атомарная правка количества/срока и отказ устаревшей формы. Полный backend-прогон: **288 passed, 6 opt-in skipped за 225 секунд**. Профильный прогон: 74 passed, 1 opt-in skipped. Frontend: **100 passed**. Ruff, Mypy, ESLint и production-build прошли; сохраняется прежнее предупреждение о JS-бандле больше 500 kB. Во время проверки миграции исправлено прежнее несоответствие имён двух индексов review_status/source_task_id в ORM и миграции; данные и сами индексы не удалялись.

Браузер на реальном PostgreSQL проверил создание «На продажу», ручное создание тестовой вещи с 2 парами, изменение названия/остатка до 3 пар/места/срока одной формой, true → false, сохранность после перезагрузки, добавление фото и загруженную миниатюру. Отключённый атрибут скрыт у новой вещи, а сохранённое false остаётся доступным в существующей. После проверки флаг снова включён. На ширине 390 px форма не выходит за экран, кнопка сохранения доступна; после переноса показана одна актуальная строка с 3 парами. Переключение 3 пары → 6 штук → 3 пары проверено в браузере; дробное количество, которое потребовало бы округления при переводе в пары, отклоняется. Профильные 5 frontend-тестов повторно прошли после этой защиты. Вызовов AI в этом прогоне нет. Настоящий Android и точность моделей этим эпиком заново не проверялись.

После обновления образов все 10 контейнеров запущены, `/health/ready` возвращает 200, `alembic check` сообщает `No new upgrade operations detected`. Проверка хешей всех 6 исходных промптов прошла. Созданная для проверки карточка архивирована через интерфейс; пользовательские карточки не очищались. В последней проверке формы ошибок JavaScript не было.
