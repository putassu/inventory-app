# ИСЧЕРПЫВАЮЩЕЕ ТЕХНИЧЕСКОЕ ЗАДАНИЕ К ФРОНТЕНДУ (FRONTEND_SPEC.md)

Данный документ описывает максимально подробные требования к пользовательскому интерфейсу (UI), бизнес-логике на стороне клиента и UX-взаимодействиям, опираясь на архитектуру базы данных (PostgreSQL + Qdrant) и ML-пайплайн.

---

## 1. Карточка Вещи (Item Card) и Режим редактирования
Карточка предмета — центральный элемент UI. Она не должна быть статичной: пользователи должны иметь возможность редактировать данные на лету без перехода на отдельные страницы.

### 1.1 Редактируемые атрибуты и медиа
- **Inline Editing**: По клику на атрибут в карточке он переходит в режим редактирования (input / dropdown / datepicker).
- **Управление медиа**:
  - Пользователь может удалить привязанную фотографию или загрузить новую.
  - Можно прослушать, удалить или перезаписать **голосовую заметку** (`audio_url`). Замена аудио должна триггерить перезапуск транскрипции (через пайплайн или отдельный эндпоинт).
  - При клике на фото открывается полноэкранная галерея (просмотр `original_url`).
- **Удобные контролы ввода**:
  - Для дат (`expiry_date`, `remind_at`) — удобный **Календарик (Date Picker)**.
  - Для количества (`quantity`) — явные кнопки `+` и `-`, а также поле ручного ввода цифрами. Блокировка ввода `NaN` или букв. При `quantity <= 0` предмет автоматически переводится в статус `depleted` и уходит в корзину/архив (согласно настройке `auto_archive_depleted`).
  - Для категорий (`primary_category`, `secondary_categories`) — **Выпадающие списки (Dropdown / Select)** с иконками.
  - Для тегов и синонимов — **Комбобоксы (Tags Input)**, где можно выбрать из существующих в базе или вписать новый (нажать Enter).

### 1.2 Корзина и Восстановление
- **Кнопка "Удалить"**: Иконка мусорного ведра делает Soft-Delete (`archived_at = NOW()`).
- **Раздел "Корзина"**: В интерфейсе должна быть вкладка/фильтр "Корзина" (отправка `GET /items?include_archived=true`).
- **Кнопка "Восстановить"**: Внутри корзины на карточке должна быть кнопка возврата вещи в активный инвентарь (обнуляет `archived_at` и `status = completed`).

## 2. Поиск (The Core "Magic" Feature)
Поиск — это главная фишка приложения. Он должен ощущаться как магия, работая с любыми форматами данных.

### 2.1 Глобальная строка и Автокомплит
- Поле поиска закреплено в шапке (Header) приложения.
- При вводе текста мгновенно (через Debounce) вызывается `GET /inventory/search` для быстрого полнотекстового поиска (BM25) по полям `name`, `tags`, `synonyms`, `generated_desc`.
- В выпадающем списке автокомплита вещи должны группироваться по локациям, чтобы сразу было понятно, где лежит искомый предмет.

### 2.2 Мультимодальный RAG Поиск (Кнопка Магии)
- Рядом со строкой поиска находятся две кнопки: **Иконка микрофона** и **Иконка камеры/фото**.
- Пользователь может сфотографировать деталь или наговорить: "Где у меня лежат красные таблетки от головы?".
- Вызывается эндпоинт `POST /inventory/search/multimodal`, который векторизует медиа и ищет семантические совпадения в Qdrant.
- Результаты выдаются в виде карточек с показателем **Сходства (Similarity Score)** в процентах. Если сходство высокое, результат выделяется визуально.

## 3. Расписания и Напоминания (Schedules Tab)
Этот раздел управляет временем жизни предметов и задачами пользователя.

### 3.1 Цветовая индикация (Traffic Lights) по Перцентилям
- Интерфейс вычисляет и окрашивает карточки:
  - **Красный (Критично)**: Вещь просрочена или перевалила за p99 (например, 99% времени годности истекло).
  - **Оранжевый (Внимание)**: Вещь перевалила за p80/p95 (скоро испортится).
  - **Зеленый (В норме)**: Запас времени достаточен.

### 3.2 Управление расписаниями (Reminders / Cron)
- **Ручная перестановка**: Пользователь может прямо из списка перетянуть дату или нажать на календарик, чтобы перенести напоминание (`remind_at`).
- **Быстрое действие "Выполнено" (Done)**: Кнопка-галочка на уведомлении/задаче. Нажатие удаляет/отключает напоминание (сбрасывает поле `remind_at`).
- **Списание**: Кнопка "Списать" сразу переводит просроченную вещь в статус `depleted`.

## 4. Настройки пользователя (Settings & Tiers)
Раздел профиля и конфигурации должен давать детальный контроль над поведением системы и отображать статус аккаунта.

### 4.1 Статус аккаунта (User Tiers)
- В шапке приложения и в профиле всегда должна отображаться иконка текущего тарифа пользователя: **FREE** (бронза/серый), **STANDARD** (серебро), **PREMIUM** (золото/корона).
- Должен отображаться прогресс-бар или текст с количеством оставшихся запросов (лимитов) и датой истечения подписки `tier_expired_at`.

### 4.2 Меню настроек
Опираясь на структуру `UserSettings`, интерфейс должен содержать переключатели (Toggle) и ползунки (Sliders):
- **Local LLM Only (Режим параноика)**: Тумблер вкл/выкл. Полный отказ от облачных моделей. При включении должно появляться предупреждение, что ML-пайплайн будет работать медленнее.
- **Developer Mode**: Тумблер. Если включен, в UI выводятся сырые тексты ошибок и JSON-ответы от графа.
- **Auto Archive Depleted**: Тумблер. Автоматически переносить в корзину предметы с quantity = 0.
- **Аудиты (Audit Reminder Days)**: Ползунок от 0 до 365 дней. Регулирует частоту напоминаний о проверке "залежавшихся" вещей. Возможность выбрать конкретные локации для аудита (через Multi-select dropdown).
- **Часовой пояс (Timezone)**: Выпадающий список часовых поясов (важно для корректной отработки cron-уведомлений).
- **Пороги (Percentiles)**: Три ползунка для настройки p80, p95, p99 (например: Желтый при 75%, Оранжевый при 90%, Красный при 99%).

## 5. Задачи (Tasks), Progress Бары и Форма HITL
ML-пайплайн асинхронен. Фронтенд должен делать интерфейс отзывчивым даже при долгом инференсе (до 200 сек).

### 5.1 Progress Бары
- Фронтенд поллит `GET /inventory/tasks/{task_id}` раз в 2-3 секунды.
- **Этапы (Кирпичики)**: Прогресс бар визуально разбит на этапы: 
  1. Загрузка в MinIO.
  2. Gatekeeper (ASR & Безопасность).
  3. LLM Extraction (Local/Cloud).
  4. Сохранение (DB).
- Если этап пропускается (например, Gemini fallback не понадобился), он мгновенно закрашивается зеленым.
- При ожидании долгих локальных моделей прогресс-бар не должен отваливаться по таймауту браузера; показывается пульсирующая анимация "Ожидание ответа от нейросети...".

### 5.2 Форма ItemForm (HITL и Manual)
Форма `ItemForm.jsx` — универсальна.
- В режиме HITL (когда `status === 'user_action_required'`) форма предзаполняется "сырыми" данными. Сверху выводятся оригинальные миниатюры загруженных фото и текст транскрипции из аудио.
- В режиме "Ручного добавления" форма пустая.
- Важно: Поля в форме должны быть **умными**. Если выбран класс "Лекарства", динамически появляются инпуты для Срока годности. Если "Одежда" — инпуты для размера и цвета. Данные мапятся в поле `attributes` (JSONB).

## 6. Локации (Locations) и Иерархия
Система хранения базируется на древовидной структуре.

### 6.1 Дерево и Навигация
- **Tree View / Folder View**: Отображение локаций в виде папок. Хлебные крошки (Breadcrumbs) для навигации (`Спальня > Комод > Верхний ящик`).

### 6.2 Drag & Drop (Drag-and-Drop)
- Пользователь может зажать локацию мышью/пальцем и бросить в другую локацию. (Отправляется `PUT /inventory/locations/{id}/move` с `new_parent_id`). Защита от перетаскивания ящика в самого себя (на уровне UI и backend).
- Перетаскивание карточек вещей в нужную папку локации для их перемещения.

### 6.3 Расширенное удаление
При клике на удаление локации открывается Modal с 3 радио-кнопками:
1. **Удалить навсегда** (Cascade=true).
2. **Распаковать** (Cascade=false) — локация удаляется, вещи остаются в родительской локации.
3. **Эвакуировать** — появляется Dropdown для выбора локации, куда переедут вещи, после чего текущая локация удалится.
