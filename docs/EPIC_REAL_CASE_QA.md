## Медиа и приватность

- Проверены 16 исходных изображений и 9 WAV. Изображения на входе в API имеют длинную сторону не более 1600 px и `client_preprocessed=true`; WAV преобразованы браузером в PCM16 mono 16 kHz.
- Фото кейса 1 с закодированными размерами 4032×3024 после применения ориентации и сжатия стало 1200×1600, около 282 КБ вместо исходных 2,99 МБ.
- Длинная сторона миниатюр не превышает 256 px. Серверные изображения для модели не превышают 512 px; максимальный размер файла в этом наборе — 60 067 байт. Несколько фото объединены в один коллаж.
- Все источники и производные имеют `local_only`, у задач `external_calls=0`. Доверенный сервер владельца разрешён для голоса; это не внешний AI-провайдер в модели приватности приложения.
- Через браузер проверены крупное открытие обоих фото кейса 4, сохранение ручного review, фотографическая миниатюра в каталоге и два прикреплённых изображения.
- Фото/голос, расшифровки, локальные результаты и тесты исключены из Git. В публичном отчёте нет изображений, расшифровок и персональных полей документов. Техническое сопоставление case→task хранится только в игнорируемой `.cache/real-case-qa/`.

## Найденный и исправленный дефект транзакции

Во время быстрых переходов наблюдался сбой восстановления сессии. Независимая регрессия обнаружила более общий дефект: API мог отправить HTTP 200 раньше commit. При искусственной ошибке commit клиент всё равно получал 200 и cookie. Это также позволяло следующему запросу прочитать ещё не зафиксированную запись.

Общая зависимость `db_session` теперь использует `Depends(database, scope="function")`: завершение транзакции происходит до отправки ответа. Все HTTP-обработчики используют её; исключения сохраняют rollback, а `PersistedConflict` — необходимую фиксацию актуальной формы. Ошибка commit теперь даёт 500 без успешной cookie. Поведение scope описано в [официальной документации FastAPI](https://fastapi.tiangolo.com/advanced/advanced-dependencies/).

Минимальная версия FastAPI уточнена до 0.121.1; lock сохранил 0.141.1 и остальные разрешённые версии. Миграция БД не нужна. Новые тесты сначала воспроизвели оба дефекта, затем прошли после исправления. После обновления контейнера 12 последовательных перезагрузок каталога прошли без потери сессии и JS-ошибок; это smoke, а не доказательство отсутствия любых гонок.

## Улучшение формы

Фотографии источников теперь открываются кнопками в отдельном диалоге в крупном виде. На реальных этикетках маленького preview недостаточно для ручной проверки. Используется авторизованная загрузка; приватные URL не превращаются в публичные ссылки. Проверено открытие фотографии 1000×1000 и возврат в форму.

Дополнительно на ширине 320 px проверено изображение 1200×1600: диалог шириной 282 px без горизонтального переполнения. Enter открывает просмотр, Escape закрывает, фокус возвращается на исходную кнопку. Ошибка CSS-селектора в первом проверочном скрипте исправлена: нативный `dialog` имеет неявную роль, поэтому DOM-поиск `[role="dialog"]` его не находил; это не дефект приложения.

## Проверки и эксплуатация

Полный локальный backend-прогон: **187 passed, 6 skipped**. Пропуски — инфраструктурные сценарии PostgreSQL/Redis/backup, требующие отдельного включения. Frontend: **71 passed, 15 файлов**, ESLint и Docker production-build прошли. Ruff и `git diff --check` прошли. Новые локальные тесты не включаются в Git по требованию владельца.

Во время диагностики дополнительный Python-процесс был ошибочно запущен внутри API-контейнера с лимитом 192 MiB, что привело к OOM. API восстановлен с новым образом; дальнейшее чтение метаданных выполнено лёгким read-only psql напрямую в PostgreSQL. Данные и очередь сохранились, `/health/ready` вернул 200. Лимиты памяти не увеличивались; измеренное потребление восстановленного API — около 139 MiB. Этот OOM относится к диагностическому процессу, не к штатной загрузке через браузер.

Обновлены API и web; текущий frontend bundle — `index-B1RYEBzu.js`. БД, файловое хранилище и процессы очередей не пересоздавались. Образы собраны локально; публикация в GitHub не выполнялась.
