# Единый шлюз моделей LiteLLM

Дата: 10.10.2026. Адрес: `https://as.rsmu.ru/litellm`. Ключ хранится только в игнорируемом `.env.local`.

## Маршруты

| Назначение | Alias | Граница доверия |
|---|---|---|
| Первичная проверка, OCR, ASR | `local-gemma-4-e4b` | Доверенная локальная модель |
| Основное локальное распознавание | `local-gemma-4` | Доверенная локальная модель |
| Поисковые эмбеддинги | `local-bge-m3` | Доверенная локальная модель, 1024 измерения |
| Основное облачное распознавание | `gemini-3.5-flash-lite` | Внешний провайдер, только после проверки приватности |

В `/models` маленькая модель опубликована как `local-gemma-4-e4b`; вариант без префикса `local-` отсутствует. В окружении и примере конфигурации использовано фактическое имя шлюза.

Общий адрес и ключ не делают облачный alias локальным. Проверки privacy, sensitive/document, принудительной локальности и разрешения внешней обработки сохраняются. Локальный адаптер принимает только локальные alias из конфигурации и требует `INV_LITELLM_TRUSTED=true`.

## Изменения

`INV_LITELLM_URL/KEY/TRUSTED` включают общий шлюз. При пустом URL остаётся прежний режим Ollama и прямого провайдера. Обращения к шлюзу прямые, системные переменные прокси автоматически не подхватываются.

Чат и мультимодальный ввод используют `/chat/completions`; эмбеддинги — `/embeddings` с `encoding_format=float`. Порядок векторов восстанавливается по index; проверяются полнота, размерность и конечные числовые значения. Список моделей запрашивается через `/models` без генерации; наличие alias не выдаётся за проверку изображения или аудио.

Bootstrap и sync-models используют единое описание пяти логических deployment. OCR/ASR относятся к одному физическому малому alias. Основной pipeline передаёт endpoint из реестра. При смене маршрута версия deployment меняется, старые результаты health-check сбрасываются; прежние задачи не исполняются незаметно с подменённой моделью. Миграция БД не требуется. Health/capabilities учитывают LiteLLM, а не требуют работающий Ollama на ноутбуке.

Клиент отправляет `disable_fallbacks=true` и `x-litellm-num-retries: 0`, чтобы не добавлять скрытые переходы между моделями и повторы поверх очереди приложения. Основание: [отключение fallback](https://docs.litellm.ai/docs/proxy/reliability#disable-fallbacks-per-requestkey) и [управление retry](https://docs.litellm.ai/docs/routing). На самом шлюзе локальные alias должны быть настроены на локальные deployment; приложение не администрирует удалённый router. Общий GPU-slot и по одному worker job сохраняются. Текущие шаблоны промптов не менялись.

## Проверка и окружение

93 теста адаптеров, основного пайплайна, OCR и приватности прошли с MockTransport/подставными моделями: реальная облачная квота ими не расходуется. Финальные 10 тестов LiteLLM также прошли. Ruff изменённых модулей и стандартный Mypy проекта (`app/domain`, `app/settings`, 10 файлов) прошли. Расширенный Mypy по API/адаптерам/воркерам выявляет 76 ошибок типизации в 20 файлах, поэтому проверка типов всего бэкенда не объявляется пройденной. Сборка backend выполнена.

При начале работы PostgreSQL/Redis/MinIO/Qdrant были остановлены, воркеры перезапускались. Зависимости восстановлены. Windows зарезервировала диапазон 56346–56445, поэтому прежний host-порт Redis 56379 недоступен. В текущем тестовом compose он заменён на 16379; контейнеры продолжают использовать `redis:6379/14`.

Прямое подключение из Docker проверено: `/models` вернул 200. Вначале наблюдались TLS-таймауты; связь с системным прокси не подтверждена. Последующие запросы прошли без прокси, сетевые настройки приложения на него не переводились.

Выполнены последовательно пять контрольных модельных запросов:

| Проверка | Результат |
|---|---|
| Первичная Gemma, синтетическое JPEG 384×192 | Прочитала `INVENTORY 42`, корректный JSON, 5,71 с |
| Основная локальная Gemma, текст о паре носков | Корректный JSON, количество 1, единица `pair`, 8,07 с |
| BGE-M3, два текста одним запросом | Два конечных числовых вектора по 1024 измерения, 0,77 с |
| ASR, секунда тишины WAV | Проверка через кнопку администрирования: HTTP 200, структура транскрипции валидна |
| Облачная Gemini, синтетический JSON | Проверка через кнопку администрирования: HTTP 200, валидный JSON; после неё облако включено |

Облачных контрольных запросов — **один**. Проверка ASR на тишине подтверждает совместимость аудио-ввода, а не качество распознавания речи. Полный живой сценарий с фото/голосом и облачным извлечением не повторялся ради экономии квоты; маршруты пайплайна и запрет внешней передачи local-only покрыты изолированными тестами.

Реестр синхронизирован, обслуживание embeddings завершено после реального успешного вызова. Все 10 контейнеров запущены. `/health/ready` вернул 200, `saving_available=true`, `recognition_available=true`, GPU `idle`, приостановленных очередей нет. Облачная очередь имеет concurrency 1. Через браузер проверены вход, страница моделей, проверка аудио/облака и включение облака. Все 6 файлов исходных промптов совпали с SHA-256 baseline. `.env.local`, тесты и тестовые кейсы остаются в `.gitignore`; публикация в GitHub в этом эпике не выполнялась.
