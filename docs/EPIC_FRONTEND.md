# Эпик: интерфейс API v1

Новый интерфейс находится в `frontend/src/v1`; `src/main.jsx` подключает его напрямую. В работе остались React и ReactDOM. Старый интерфейс с прежними `/inventory` и `/auth` маршрутами перемещён в локальный архив `data/legacy-source-20260917/frontend/src`; пути источника и назначения проверены внутри рабочей области. Исходные материалы доступны также в общем снимке до рефакторинга.

## Реализовано

- Вход через API v1, refresh-cookie, токен доступа только в памяти. Выбор workspace сохраняет токен. Два восстановления при React StrictMode делят один запрос refresh, чтобы ротация не отзывала сессию.
- Каталог с партиями, остатками, сроками, архивом, поиском и историей. Поиск передаёт `query`; найденные кандидаты превращаются в полные карточки. Доступны все команды учёта через предложения: добавление, пополнение, движение, расход, корректировка, изменение, разделение и объединение партий, места, алиасы, присутствие, архив и восстановление. Объединение сначала требует выбрать две партии; формы изменения получают текущие значения.
- Проверка предложений строится по серверным полям. Количество передаётся строкой; выбор партий — массивом ID. Поддерживаются typed-поля `attributes.*`, отдельные решения `operation`/`unsupported_request`, выбор мест, единиц и алиасов. Исходные фото загружаются с авторизацией, временные URL освобождаются.
- Правки можно отправить непосредственно с подтверждением. Сохраняются наблюдаемые revision/hash; сетевой повтор использует тот же Idempotency-Key. HTTP 409 показывает обновлённую форму и требует нового нажатия. Сохранение отслеживается отдельно от распознавания; неудавшееся подтверждение можно повторить.
- Загрузка фото, текста и WAV при подтверждённой сервером возможности `audio_inference`; на задачу одна запись. Загрузка файлов восстанавливается после частичного сбоя. Пользователь может ограничить обработку доверенным сервером.
- Задачи, отмена, повтор обработки, ручное продолжение из допустимых состояний. Ручное продолжение открывает предложение дочерней задачи. Настройки используют реестр `fields`, значения и версии API; административное применение следует после предварительной проверки, включая последствия сокращения хранения.
- Уведомления можно скрывать с проверкой версии. Экспорт ZIP загружается с авторизацией. Удаление требует отдельного предпросмотра и явного подтверждения; список отложенных удалений виден при включении архива и позволяет восстановление до физической очистки.
- Подраздел напоминаний позволяет создавать, менять и отключать правила сроков для лекарств, продуктов и документов: категории, места, дни до срока, часовой пояс, время доставки, тихие часы, повторы просрочки, группировка и приватность. Правила меняются с ожидаемой версией; длинный список поддерживает пагинацию.
- Административный подраздел показывает модели, проверяет соединение синтетическим запросом, разрешает включение после проверки и перевод в обслуживание. Очереди можно приостанавливать и возобновлять. Восстановление GPU требует введённой причины, отдельного подтверждения остановки inference и текущего fencing token; изменение токена сбрасывает подтверждение.
- Доступны readonly аудит с пагинацией и метрики, перестроение поиска с опросом фактического `/admin/jobs/{id}`, предпросмотр и запуск очистки. Настройки с `editable=false` недоступны для изменения; dry-run политики хранения показывает дополнительные цели очистки, ближайший запуск и сохранённые отсрочки.
- Несколько выбранных предложений можно объединить в общую форму по их ревизиям. Объединение не применяет учёт; требуется отдельное общее подтверждение. `default_privacy` задаёт начальное состояние формы загрузки, `compact_view` меняет плотность каталога.
- Мобильная раскладка, русские подписи и метаданные страницы, системный шрифт. Запросов к Google Fonts нет. Форматирование закреплено локальным Prettier, комментарии на русском.

## Запуск

`npm ci`, затем `npm run dev` в `frontend`. Vite слушает `127.0.0.1:3000` и проксирует `/api/v1` и `/health` на `127.0.0.1:8000`.

`frontend/Dockerfile` собирает статические файлы и запускает nginx. Nginx проксирует API к сервису `api:8000`, сохраняет Host, поддерживает SPA и не кэширует HTML. API должен разрешать фактический Origin страницы в настройке CORS; это требуется в том числе для cookie-запросов. Секретов в frontend нет.

Vitest ограничен двумя процессами, чтобы не расходовать память на число процессов по количеству ядер.

## Проверки

Проверено 17.09.2026: `npm run lint` — без замечаний; `npm test` — 31 тест в 6 файлах прошёл; `npm run build` — успешно, JS около 246 КБ (gzip около 76 КБ). Контрактные UI-тесты покрывают сессию и параллельный refresh, inline-правку 20→19, повтор запроса, обновление формы при 409, merge-массив, вложенную дозировку, явный выбор операции, существующую карточку при пополнении, источник перемещения, capability аудио, гидратацию поискового результата, версионирование настроек и административный dry-run. Дополнительно проверены GPU recovery, блокировка непроверенной модели, maintenance/version, возобновление очереди, создание/изменение/отключение правил, отклонение дробных дней, запрет изменения readonly параметра, приватность по умолчанию и объединение предложений без автоподтверждения. Финальный осмотр сверил фактические маршруты и payload API; исправлены отображение `running`/`completed` очистки, завершение опроса отозванного экспорта и выход после истечения access token.

## Границы проверки

Vitest проверяет UI с ответами API заданной структуры. Это не браузерный E2E с реальными моделями; интеграционные и модельные проверки записаны в других отчётах. Backup/restore выполняется через CLI. Массовые ingestion batches доступны через API; интерфейс позволяет объединять уже полученные предложения. Голос загружается готовым WAV. Интерфейс выбирает первое доступное workspace. Отдельные экраны tracing/replay и восстановления старой ревизии настроек отсутствуют. История карточки и варианты алиасов ограничены первой страницей соответствующих API. Смысловая интерпретация сроков и проверка допустимости всех действий остаются на сервере.
