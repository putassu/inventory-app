# ADR-001: новая схема учёта и сохранение исходных промптов

Старая модель связывает количество непосредственно с карточкой и не содержит долговечных подтверждений. Безопасное расширение потребовало бы сохранять два несовместимых пути записи.

Решение: один модульный backend, схема PostgreSQL `inventory`, Alembic и единый сервис команд. Старые таблицы в `public` не изменяются автоматически. Перенос старых данных выполняется отдельной CLI-командой через проверяемые ручные предложения; исходные данные сохраняются для сверки. Откат развёртывания возвращает старый код и `public`, а не пытается разрушительно преобразовать новый журнал.

Персональная нагрузка допускает короткую блокировку строки workspace на время команды. Она упрощает стабильный порядок блокировок, предотвращает гонки дерева и отрицательные остатки. Внешние сервисы не вызываются внутри этой транзакции. ML и ожидание review блокировок не удерживают.

Настроенные промпты сохраняются побайтно. Дополнительная системная инструкция уточняет unknown, недоверенный ввод и отсутствие полномочий на исполнение. Старый JSON преобразуется в типизированное извлечение и затем в предложение; UUID проверяются по выданным кандидатам, синонимы не записываются автоматически.

Для тестов используется SQLite и отдельная PostgreSQL БД. SQLite не заменяет проверку конкуренции PostgreSQL. Продакшен запускается только после Alembic.
