# Отчёт о рефакторинге «Инвентаризатора»

Основание: AGENT.md. Работа начата 17.09.2026; уточнения бэкенда и итоговые проверки — 21.09.2026. Модель предлагает, пользователь подтверждает, PostgreSQL атомарно применяет и хранит результат.

## Сохранение исходного состояния

Исходники с незакоммиченными изменениями пользователя сохранены в `data/refactor-before-20260917.zip`. Старые модули перенесены в игнорируемый `data/legacy-source-20260917` и исключены из импортов, тестов и образов. История Git, прежняя схема `public`, рабочие медиа и исходный `.env` сохранены. Перенос прежних AI-данных доступен через `legacy-preview` с подтверждением.

Все **6 исходных промптов сохранены побайтно** относительно начала работы: `python -m app.cli verify-prompts`. Baseline — `prompt-baseline.json`; совместимость и защитные правила находятся вне исходных шаблонов.

## Итоговые проверки

**186 passed за 166,38 секунды**, без предупреждений и пропусков в финальном прогоне с включёнными PostgreSQL concurrency, настоящим Redis loss и backup/restore. Ruff, mypy по domain/settings и проверка промптов проходят. Поставляются OpenAPI/JSON Schema, миграции, CI, Compose и runbook.

Backend-образ пересобран и проверен через nginx: HTTP-вход, загрузка настоящего фото 4032×3024 при лимите API 192 MiB, ротация HttpOnly cookie, запрет чужого Origin, отсутствие карточки до confirm, scheduler и CPU worker. Результат — [container-smoke.json](container-smoke.json), 8,72 секунды. Тестовые зависимости имеют суммарный лимит 640 MiB, без старых volumes; память моделей учитывается отдельно.

Устранены полноразмерные RGBA-копии в подготовке JPEG. Две параллельные обработки фото 4032×3024 в контейнере без swap уложились в **190,83 MiB RSS** при лимите 256 MiB. [Измерение](media-memory-smoke.json). Файловые пиксели декодирует CPU worker; API проверяет структуру файла и размеры.

После проверок все девять контейнеров `inventory-refactor-test` остановлены для освобождения памяти; контейнеры и их тестовые данные сохранены. Тестовый Compose не предусматривает постоянные named volumes, поэтому stop не следует заменять удалением/пересозданием контейнеров в расчёте на сохранность данных.

Повторный сквозной сценарий с разрешёнными фото/WAV `tests/cases/case_1` прошёл за **123,23 секунды**: голос распознан, 3 попытки, local_only, корректная receive_stock-форма, **0 карточек до confirm**. Отдельная явная ручная операция применена через arq, поиск нашёл карточку, reindex переключил alias. [Результат](stack-smoke.json). Ключ доверенного LiteLLM хранится только в игнорируемом `.env.local`.

Маленькая этикетка выявила выдуманную моделью дату: [первоначальный неудачный результат](small-label-before-guard.json). Теперь дата с small_tile становится unknown, если она не указана в тексте пользователя, с объяснением в форме. [Повторная проверка](small-label-smoke.json) прошла за **61,30 секунды**. Это защита формы, а не заявление об отсутствии галлюцинаций у модели.

## Границы и эксплуатация

[Матрица T-01…T-80](ACCEPTANCE.md) различает прямое покрытие, mocks и оставшиеся границы. Точность всех полей всех личных кейсов не измерялась. Автоматические detail-pass и полная калибровка датасета не заявляются; нечитаемые поля остаются unknown. Физический kill ОС сразу после commit заменён направленной проверкой границы commit/ack.

Внешний недоверенный AI вживую не использовался; адаптер/ошибки/cooldown проверены MockTransport. Dataset writer, кэш списков и verbose с raw payload не поставляются: включение явно запрещено. Push отсутствует, inbox работает. OpenTelemetry/collector не развёртывались; для MVP есть структурированные события и сохранённые времена стадий.

Backup/restore поставляется и проверен. Расписание на хосте и копирование на другой диск настраиваются при установке; системная задача ОС автоматически не создавалась. [Порядок эксплуатации](RUNBOOK.md), [контракт для будущего клиента](API_MEDIA_PROGRESS.md).

До уточнения 21.09 была обновлена совместимость web-клиента и пройден 31 компонентный тест. После указания владельца фронтенд исключён из текущего эпика. Его прежний [отчёт](EPIC_FRONTEND.md) сохранён; новые UI-функции не являются условием приёмки этого бэкенда.
