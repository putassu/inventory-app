Исправлен маршрут OCR: используется endpoint первичной доверенной модели вместо жёсткого обращения к Ollama. Остановленный Ollama на хосте запущен в один поток. Назначение OCR и ошибка соединения пояснены. Проверены 30 профильных backend-тестов, 104 frontend-теста и реальное OCR в мобильной ширине браузера. ## Итоговые проверки

**186 passed за 166,38 секунды**, без предупреждений и пропусков в финальном прогоне с включёнными PostgreSQL concurrency, настоящим Redis loss и backup/restore. Ruff, mypy по domain/settings и проверка промптов проходят. Поставляются OpenAPI/JSON Schema, миграции, CI, Compose и runbook.

Результат — [container-smoke.json](container-smoke.json), 8,72 секунды. Тестовые зависимости имеют суммарный лимит 640 MiB, без старых volumes; память моделей учитывается отдельно.

Устранены полноразмерные RGBA-копии в подготовке JPEG. Две параллельные обработки фото 4032×3024 в контейнере без swap уложились в **190,83 MiB RSS** при лимите 256 MiB. [Измерение](media-memory-smoke.json). Файловые пиксели декодирует CPU worker; API проверяет структуру файла и размеры.

После проверок все девять контейнеров `inventory-refactor-test` остановлены для освобождения памяти; контейнеры и их тестовые данные сохранены. Повторный сквозной сценарий с разрешёнными фото/WAV `tests/cases/case_1` прошёл за **123,23 секунды**: голос распознан, 3 попытки, local_only, корректная receive_stock-форма, **0 карточек до confirm**.
