С начала этого эпика новых модельных попыток не зарегистрировано. Старые описания девяти ожидающих задач в предыдущих отчётах являются историческими: продолжать их больше не нужно.

На момент передачи работают API, web, CPU и scheduler. ML остановлен; `default`, `bulk`, `cloud`, `maintenance` на паузе, `cpu` доступна для ручного сохранения и подготовки файлов. GPU остаётся в карантине. Приложение больше не отправляет старые запросы, но физическая остановка уже отправленного вычисления на удалённом сервере этим не доказывается. Восстановление описано в [RUNBOOK](RUNBOOK.md).

## Исправления скриншотов

1. Пустое назначение при архивировании места теперь означает системное «Место не указано». Поле не требует искусственного выбора.
2. Архивирование переносит остатки, включая остатки архивных вещей. Общая команда перемещения активной вещи больше не вызывается для архивного содержимого. Дочерние места сохраняются: при переносе в системное место они становятся верхнеуровневыми. Проверки циклов и несовместимых неизвестных остатков сохранены.
3. После архивации открытой страницы места интерфейс переходит к родителю или списку, а не запрашивает уже архивированное место с последующим 404.
4. При совпадении названия в review видны найденные вещи и явная кнопка «Это другая вещь — создать отдельно». Решение не скрывается в дополнительных свойствах. Аналогичное разрешение доступно в ручной форме.

Архивирование не вызывает LLM. Подтверждение действия в диалоге и обычные серверные проверки нужны для сохранности содержимого; отдельной страницы проверки распознавания в этом пути нет.

## Новый пользовательский путь

- «Мои вещи» → «Добавить вещь»: фото, название, количество/единица и место. Категория, срок, точность и прочие сведения раскрываются по запросу.
- Место → секция → «Добавить вещь»: место уже выбрано. Создавать секции, редактировать и архивировать можно через «Ещё».
- Фотографии доступны при ручном поступлении и создании/редактировании места. Миниатюры показаны в списках, крупное фото открывается отдельно. Тип места подписан и дополнен 📦 или 🏠.
- Переход из ручной формы к фото/голосу сохраняет подготовленные фото, название и контекст места. Из composer можно открыть ручное заполнение с уже выбранными фото и текстом. Передача работает в памяти вкладки, без сохранения файлов в localStorage; данные очищаются при смене сессии/рабочей области.
- Принятое AI-задание сразу появляется карточкой в каталоге и выбранном месте. Синий статус означает обработку, жёлтый — необходимость проверить результат, красный — ошибку. Статус всегда подписан текстом. Для существующей вещи отметка появляется на её карточке.
- Отменённые добавления исчезают из каталога, завершённые заменяются сохранённой вещью. Черновики обработки не увеличивают подтверждённые остатки.
- В карточке раздел «Где и сколько» показывает места, количество и сроки. Обязательный выбор новой/существующей партии, технические заголовки партий, разделение и объединение убраны из обычного пути. Внутренняя модель lot сохранена для разных сроков, остатков и истории.
- Успешное сообщение сохранения автоматически скрывается; ожидающее или ошибочное подтверждение остаётся доступным.

## Backend и ограничение нагрузки

`receive_stock`, `create_location`, `update_location` принимают `media_ids`. Изображения проверяются в текущей рабочей области, связываются с сущностью при применении подтверждения; миниатюра до 256 px создаётся на CPU без задачи распознавания. Места возвращают `photos` того же формата, что вещи. Экспорт включает фотографии мест; общий файл, используемый местом, остаётся доступным после удаления связанной вещи.

Новый `queue.max_pending_total` по умолчанию равен **1**, глобально для развёртывания. Приём сериализован блокировкой строки GPU slot в PostgreSQL; подсчитываются AI-задачи в `accepted`, `preparing`, `queued`, `running`, `retry_wait`. `waiting_for_review` уже не занимает inference-очередь. Следующая задача при занятом лимите получает 429 `ADMISSION_LIMIT`; ручное сохранение не блокируется. Default `queue.max_pending_per_user` также снижен до 1; ранее сохранённые значения настроек не перезаписываются.

В capabilities добавлены `max_pending_ai_tasks`, `ai_processing_paused`; в task DTO — `context`, `preview_media_id`, `diagnostics_only`. После CPU-подготовки preview переключается на миниатюру. При паузе maintenance уже отправленный в Redis outbox также не начинает индексирование или обслуживание.

Это ограничение приёма, а не замена существующего единственного GPU slot, fencing и карантина. Реальные тесты моделей должны выполняться последовательно с ожиданием завершения предыдущего. На слабом сервере нельзя увеличивать число воркеров или запускать параллельные диагностические model-health вызовы.

Миграции БД не нужны. Все шесть настроенных промптов сохранены без изменений. Inference по-прежнему получает один коллаж до 512 px; транспортные фото и миниатюры имеют отдельные размеры.
